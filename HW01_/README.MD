# 函數呼叫機制解析 (Function Call Mechanism)

這個編譯器實作了一個基於**堆疊幀 (Stack Frame)** 的虛擬機來處理函數呼叫。每一次的函數執行都會在堆疊 (Stack) 上建立一個新的「幀 (Frame)」，用來隔離各個函數的區域變數，並確保執行完畢後能正確跳回原本的呼叫位置。

以下是該機制的完整拆解：

---

## 1. 核心資料結構：堆疊與幀 (Stack & Frame)

虛擬機使用陣列 `stack[1000]` 來模擬記憶體中的呼叫堆疊，並用 `sp` (Stack Pointer) 指向目前正在執行的函數幀。

每個 `Frame` 結構包含了該次函數執行的所有狀態：
* **`names` / `values` / `count`**：用來儲存該函數內的「區域變數」名稱與數值。
* **`ret_pc`**：**返回位址**。記錄當函數執行完畢後，程式計數器 (PC) 應該跳回哪個指令繼續執行。
* **`ret_var`**：**回傳值接收者**。記錄 Caller (呼叫者) 要用哪個變數來接收這個函數的回傳結果 (例如 `t1 = call func`)。
* **`incoming_args` / `formal_idx`**：用來暫存從 Caller 傳遞進來的參數值，等待進入函數體後綁定到對應的變數名稱上。

---

## 2. 負責函數呼叫的中間碼指令 (IR)

語法解析器 (Parser) 會將函數呼叫翻譯成以下幾種四元組 (Quadruples) 指令：

* `PARAM <arg>`：將參數推入參數暫存區。
* `CALL <func_name> <arg_count> <result_var>`：觸發呼叫，切換堆疊幀並跳轉 PC。
* `FUNC_BEG <func_name>`：標記函數的進入點。
* `FORMAL <var_name>`：將傳入的參數綁定到函數的區域變數名稱。
* `RET_VAL <value>`：函數執行完畢，設定回傳值並銷毀目前的堆疊幀。
* `FUNC_END <func_name>`：標記函數的結束點。

---

## 3. 完整的生命週期 (以 `y = add(1, 2)` 為例)

函數呼叫的實際執行分為 4 個關鍵階段：

### 階段一：準備參數 (Parameter Passing)
當遇到函數呼叫時，虛擬機不會立刻跳轉，而是先處理參數。
遇到 `PARAM` 指令時，會將要傳遞的值（例如 `1` 和 `2`）推入一個獨立的全域暫存堆疊 `param_stack` 中。

### 階段二：觸發呼叫 (The Call)
遇到 `CALL add 2 y` 指令時，虛擬機會執行以下環境切換：
1. **尋找目標**：透過 `func_names` 陣列找到 `add` 函數的指令起始位址 (`target_pc`)。
2. **建立新幀**：`sp++`，將堆疊指標推向下一層。
3. **儲存上下文**：在新幀中紀錄返回位址 (`ret_pc = pc + 1`)，以及負責接收回傳值的變數名稱 (`ret_var = "y"`)。
4. **轉移參數**：從暫存的 `param_stack` 中取出 2 個參數，存入新幀的 `incoming_args` 陣列中。
5. **跳轉執行**：將程式計數器 `pc` 修改為 `target_pc`，正式進入 `add` 函數。

### 階段三：參數綁定 (Formal Binding)
跳轉後，`add` 函數的開頭會是 `FUNC_BEG`，接著是 `FORMAL a` 與 `FORMAL b`。
當虛擬機執行 `FORMAL` 時，會依照順序從 `incoming_args` 中取出數值，並使用 `set_var()` 將它們註冊為目前這個新幀的區域變數（即 `a = 1`, `b = 2`）。
