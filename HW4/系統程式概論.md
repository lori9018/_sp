## 1. 什麼是系統程式？

### 1.1 定義

系統程式（System Programming）是指撰寫**提供服務給其他軟體**的程式，而非直接給終端使用者使用的應用程式。系統程式是應用軟體與硬體之間的橋樑。

典型的系統程式包含：

- **作業系統**（Operating System）
- **編譯器**（Compiler）
- **組譯器**（Assembler）
- **連結器**（Linker）
- **載入器**（Loader）
- **裝置驅動程式**（Device Driver）
- **系統工具**（System Utilities）

### 1.2 系統程式 vs 應用程式

| 特性 | 系統程式 | 應用程式 |
|------|---------|---------|
| 目的 | 管理資源、提供服務 | 解決使用者問題 |
| 執行環境 | 核心模式 / 使用者模式 | 主要使用者模式 |
| 硬體存取 | 可直接存取 | 需透過系統呼叫 |
| 生命週期 | 常駐背景執行 | 按需啟動結束 |
| 語言 | C、C++、Rust、Assembly | 任何語言 |

### 1.3 為什麼學習系統程式？

- 深入理解電腦的運作原理
- 寫出更高效、更穩定的程式
- 為嵌入式系統、作業系統開發打好基礎
- 掌握記憶體管理、並行控制等關鍵技能

## 2. 計算機硬體基礎

### 2.1 馮紐曼架構（Von Neumann Architecture）

現代電腦大多遵循馮紐曼架構，包含四大子系統：

```
┌──────────┐    ┌──────────┐
│   CPU    │◄──►│  記憶體   │
│ (控制+算數)│    │ (指令+資料)│
└────┬─────┘    └──────────┘
     │
     ▼
┌──────────┐
│  I/O 裝置 │
└──────────┘
```

- **中央處理器（CPU）**：包含控制單元（CU）與算術邏輯單元（ALU）
- **記憶體**：儲存指令與資料（唯讀記憶體與隨機存取記憶體）
- **輸入／輸出裝置**：與外界溝通

### 2.2 CPU 內部架構

**暫存器（Registers）**：

| 分類 | 範例 | 功能 |
|------|------|------|
| 通用暫存器 | RAX, RBX, RCX, RDX | 儲存運算元與結果 |
| 指標暫存器 | RSP, RBP | 堆疊指標、基底指標 |
| 指令指標 | RIP | 指向下一道指令位址 |
| 旗標暫存器 | RFLAGS | 記錄運算狀態（溢位、零、負號等） |

### 2.3 指令週期（Instruction Cycle）

每道指令的執行可分為三個階段：

1. **擷取（Fetch）**：從記憶體讀取指令
2. **解碼（Decode）**：控制單元解讀指令
3. **執行（Execute）**：ALU 或記憶體執行操作

```
Fetch → Decode → Execute
   ▲                  │
   └──────────────────┘
```

### 2.4 中斷（Interrupt）

中斷是硬體或軟體向 CPU 發送的信號，告訴 CPU 需要立即處理事件。

- **硬體中斷**：由 I/O 裝置、計時器等硬體產生
- **軟體中斷**：由程式執行 `INT` 指令或系統呼叫產生
- **例外（Exception）**：由異常狀況（如除以零）產生

中斷處理流程：

1. CPU 完成當前指令
2. 儲存當前狀態（程式計數器、旗標等）
3. 載入中斷處理程式的位址
4. 執行中斷服務常式（ISR）
5. 恢復原來程式的執行

## 3. 作業系統核心概念

### 3.1 作業系統的角色

- **資源管理**：管理 CPU、記憶體、I/O 裝置等資源
- **抽象化**：提供檔案、行程、socket 等抽象概念
- **隔離**：保護不同行程不會互相干擾
- **排程**：決定誰在何時使用 CPU

### 3.2 核心模式 vs 使用者模式

現代 CPU 提供至少兩種執行模式：

| 模式 | 特權層級 | 可執行操作 |
|------|---------|-----------|
| 核心模式（Ring 0） | 最高 | 任何指令，包括硬體存取 |
| 使用者模式（Ring 3） | 最低 | 受限指令集，需透過系統呼叫 |

切換模式需透過**系統呼叫**或**中斷**。

### 3.3 系統呼叫（System Call）

系統呼叫是使用者程式請求核心服務的標準介面。

常見的系統呼叫分類：

```c
// 行程控制
fork();   // 建立行程
exec();   // 執行程式
exit();   // 結束行程

// 檔案操作
open();   // 開啟檔案
read();   // 讀取資料
write();  // 寫入資料
close();  // 關閉檔案

// 行程間通訊
pipe();   // 建立管道
shmget(); // 取得共享記憶體
semget(); // 取得號誌

// 網路
socket(); // 建立通訊端
bind();   // 繫結位址
listen(); // 監聽連線
```

## 4. 行程管理

### 4.1 行程（Process）定義

行程是**執行中的程式實體**，包含：

- 程式碼（Text Section）
- 資料（Data Section）
- 堆疊（Stack）
- 堆積（Heap）
- 暫存器狀態
- 行程控制區塊（PCB）

### 4.2 行程控制區塊（PCB）

PCB 是核心維護的資料結構，儲存：

```
┌────────────────────────┐
│  PCB (每個行程一個)      │
├────────────────────────┤
│  行程 ID (PID)         │
│  狀態 (Running/Ready/  │
│        Waiting/...)    │
│  程式計數器             │
│  CPU 暫存器             │
│  記憶體界限             │
│  開啟檔案列表           │
│  CPU 排程資訊           │
│  I/O 狀態               │
└────────────────────────┘
```

### 4.3 行程狀態

```
   New ──► Ready ──► Running ──► Terminated
             │            │
             │            ▼
             │         Waiting
             │            │
             └────────────┘
```

- **New**：行程剛被建立
- **Ready**：準備好可使用 CPU
- **Running**：正在使用 CPU
- **Waiting**：等待 I/O 或事件
- **Terminated**：執行完畢

### 4.4 行程建立（fork 模型）

Unix 系統中，行程透過 `fork()` 建立：

```c
#include <unistd.h>
#include <stdio.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("我是子行程，PID = %d\n", getpid());
    } else if (pid > 0) {
        printf("我是父行程，子行程 PID = %d\n", pid);
    } else {
        perror("fork 失敗");
    }
    return 0;
}
```

`fork()` 會複製父行程的記憶體空間，子行程從 `fork()` 回傳處繼續執行。

### 4.5 行程終止

- 正常終止：`exit()` 或 `return`
- 異常終止：接收到訊號（如 `SIGKILL`）
- 父行程需呼叫 `wait()` 收集子行程的結束狀態，避免殭屍行程

## 5. 執行緒與並行

### 5.1 執行緒（Thread）定義

執行緒是 CPU 排程的最小單位，一個行程內可包含多個執行緒，共享同一份記憶體空間。

### 5.2 執行緒 vs 行程

| 項目 | 行程 | 執行緒 |
|------|------|--------|
| 記憶體空間 | 獨立 | 共享 |
| 資源消耗 | 高 | 低 |
| 建立速度 | 慢 | 快 |
| 通訊方式 | IPC（管道、訊息等） | 直接讀寫共享記憶體 |
| 隔離性 | 高（彼此不受影響） | 低（一個掛了全部掛） |

### 5.3 POSIX 執行緒（pthreads）

```c
#include <pthread.h>
#include <stdio.h>

void* worker(void* arg) {
    int id = *(int*)arg;
    printf("執行緒 %d 正在工作中\n", id);
    return NULL;
}

int main() {
    pthread_t t1, t2;
    int id1 = 1, id2 = 2;

    pthread_create(&t1, NULL, worker, &id1);
    pthread_create(&t2, NULL, worker, &id2);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
```

編譯時需加上 `-lpthread`。

### 5.4 使用者層級 vs 核心層級執行緒

| 類型 | 管理方式 | 優點 | 缺點 |
|------|---------|------|------|
| 使用者層級（ULT） | 使用者空間的執行緒庫 | 切換快、無需核心介入 | 一個執行緒阻塞會阻塞整個行程 |
| 核心層級（KLT） | 由核心排程 | 可善用多核心 | 切換成本較高 |

## 6. CPU 排程

### 6.1 排程目標

- **CPU 使用率**：盡量讓 CPU 忙碌
- **吞吐量**：單位時間內完成的行程數
- **周轉時間**：從行程到達到完成的總時間
- **等待時間**：行程在 Ready Queue 中等待的時間
- **回應時間**：從提出請求到獲得首次回應的時間

### 6.2 常見排程演算法

#### 先來先服務（FCFS）

非搶佔式，按到達順序執行。

```
行程   到達時間  執行時間
P1      0        24
P2      0        3
P3      0        3

順序：P1 → P2 → P3
平均等待：(0 + 24 + 27) / 3 = 17
```

#### 最短工作優先（SJF）

選擇執行時間最短的行程先執行。

```
順序：P2 → P3 → P1
平均等待：(0 + 3 + 6) / 3 = 3
```

SJF 在理論上是最優的，但無法預知未來執行時間。

#### 優先權排程（Priority Scheduling）

每個行程有優先權，優先權高的先執行。可能造成**無窮阻塞（Starvation）**，可透過**老化（Aging）**解決。

#### 循環式排程（Round Robin, RR）

每個行程分配固定的時間配額（Time Quantum），時間到就切換給下一個行程。

- 時間配額太大 → 退化成 FCFS
- 時間配額太小 → 上下文切換開銷過大
- 典型值：10–100ms

### 6.3 多層回饋佇列（Multilevel Feedback Queue）

現代作業系統常用的策略：

- 多個佇列，不同優先權
- 新行程先進入最高優先權佇列
- 用完時間配額還沒結束，降級到下一層
- 防止飢餓，定期提升所有行程優先權

## 7. 記憶體管理

### 7.1 記憶體位址

- **邏輯位址**（Logical Address）：CPU 產生的位址
- **實體位址**（Physical Address）：記憶體實際的位址
- **邏輯位址空間 → 實體位址空間** 透過 MMU（Memory Management Unit）轉換

### 7.2 連續記憶體配置

- **固定分割**：將記憶體分割成固定大小的區塊
  - 缺點：內部斷裂（Internal Fragmentation）
- **動態分割**：按需求分配
  - 缺點：外部斷裂（External Fragmentation）
  - 可透過壓縮（Compaction）解決

### 7.3 分段（Segmentation）

將行程的記憶體分成邏輯區段：

```
┌──────────┐
│  程式碼   │  ── 唯讀、可共享
├──────────┤
│  資料     │  ── 可讀寫
├──────────┤
│  堆疊     │  ── 後進先出成長
├──────────┤
│  堆積     │  ── 動態配置成長
└──────────┘
```

分段位址：`<段編號, 段內偏移>`

### 7.4 分頁（Paging）

將實體記憶體與邏輯記憶體都分割成固定大小的區塊：

- **頁框（Frame）**：實體記憶體的單位
- **頁面（Page）**：邏輯記憶體的單位
- **頁表（Page Table）**：記錄頁面對應到哪個頁框

```
邏輯位址 = <頁面編號 p, 頁內偏移 d>

       頁表
  p ──────► 頁框編號 f
                │
                ▼
實體位址 = f × 頁框大小 + d
```

### 7.5 轉譯後備緩衝區（TLB）

TLB 是 MMU 內部的快取，加速位址轉換：

- TLB 命中：一次記憶體存取
- TLB 失誤：兩次記憶體存取（查頁表 + 資料存取）

## 8. 虛擬記憶體

### 8.1 核心概念

虛擬記憶體讓每個行程擁有獨立的、連續的、大小可超過實體記憶體的位址空間。

- **虛擬位址** → **實體位址** 的對映由核心與 MMU 共同管理
- 程式只需看到虛擬位址，無需關心實體記憶體布局

### 8.2 分頁的需求（Demand Paging）

只有當程式真正存取某個頁面時，才將它載入到實體記憶體。

- 優點：減少記憶體使用，加快啟動速度
- 缺點：可能發生**頁面錯誤（Page Fault）**

### 8.3 頁面置換

當記憶體已滿，需載入新頁面時，必須置換掉某個舊頁面。

**常見置換演算法**：

| 演算法 | 策略 | 優缺點 |
|--------|------|--------|
| FIFO | 置換最早載入的頁面 | 簡單，但可能有 Belady 異常 |
| LRU | 置換最久未使用的頁面 | 效能好，但實作成本高 |
| Clock | 近似 LRU 的環狀掃描 | 實務上常用，成本適中 |
| 最佳（OPT） | 置換未來最晚才用到的 | 理論最優，無法實作 |

### 8.4 核心記憶體分配

核心本身也需要管理記憶體，常見機制：

- **夥伴系統（Buddy System）**：將記憶體以 2 的冪次分割
- **slab 分配器**：針對特定結構物件的快取分配

## 9. 檔案系統

### 9.1 檔案概念

檔案是儲存裝置上的資料抽象，作業系統提供統一的介面來操作。

### 9.2 目錄結構

```
/ (root)
├── bin/      使用者可執行程式
├── sbin/     系統管理程式
├── etc/      設定檔
├── dev/      裝置檔案
├── proc/     行程資訊（虛擬檔案系統）
├── tmp/      暫存檔案
├── usr/      共用資源
└── var/      可變資料（log、資料庫等）
```

### 9.3 檔案系統實作

檔案系統需管理：

- **超級區塊（Superblock）**：描述整個檔案系統的資訊
- **inode**：記錄每個檔案的中繼資料（大小、權限、位置等）
- **資料區塊**：實際儲存檔案內容

#### inode 結構範例（ext2）：

```
┌──────────────────┐
│  權限 / 類型      │
│  擁有者 / 群組     │
│  檔案大小          │
│  時間戳記          │
│  12 個直接區塊指標  │  ── 小型檔案
│  1 個間接區塊指標   │  ── 稍大檔案
│  1 個雙重間接區塊指標│  ── 更大檔案
│  1 個三重間接區塊指標│  ── 超大檔案
└──────────────────┘
```

### 9.4 FAT 與 NTFS

- **FAT32**：簡單、相容性高，單檔最大 4GB
- **NTFS**：支援日誌、權限、壓縮、加密、單檔最大 16EB

### 9.5 虛擬檔案系統（VFS）

VFS 提供統一的檔案操作介面，讓不同檔案系統可以在同一個系統中共存：

```
應用程式
    │
    ▼
   VFS 層  (read, write, open...)
    │
    ├── ext4
    ├── NTFS
    └── tmpfs
```

## 10. 輸入／輸出系統

### 10.1 I/O 硬體架構

```
CPU ──┬── 匯流排 ── 記憶體
      │
      └── 匯流排 ── I/O 控制器 ── 裝置
```

I/O 裝置透過**I/O 控制器**與系統溝通，常見的控制器有：

- SATA 控制器（硬碟）
- USB 控制器
- NVMe 控制器（SSD）
- 網路卡

### 10.2 I/O 控制方式

#### 程式控制 I/O（Programmed I/O）

CPU 反覆檢查裝置狀態，浪費 CPU 時間。

```c
while (!(status_port & READY))
    ; // busy wait
data = data_port;
```

#### 中斷驅動 I/O（Interrupt-Driven I/O）

裝置準備好後發出中斷，CPU 再處理，效率更高。

#### 直接記憶體存取（DMA）

DMA 控制器直接在裝置與記憶體之間傳輸資料，完成後才中斷 CPU。

```
CPU 啟動 DMA 傳輸 → DMA 控制器搬資料 → DMA 完成中斷 CPU
```

### 10.3 緩衝（Buffering）

- **單緩衝**：核心提供一塊緩衝區
- **雙緩衝**：一個在消費、一個在生產，交替使用
- **環形緩衝**：固定大小環狀佇列，適合串流資料

## 11. 系統呼叫

### 11.1 系統呼叫的流程

以 `read()` 為例：

```
使用者程式
    │
    │  read(fd, buf, count)
    ▼
C 函式庫（glibc）
    │
    │  將參數放入暫存器
    │  執行 syscall / int 0x80
    ▼
核心（sys_read）
    │
    │  檢查權限
    │  從檔案系統讀取資料
    │  複製到使用者空間
    ▼
返回使用者程式
```

### 11.2 x86-64 Linux 系統呼叫約定

| 暫存器 | 用途 |

組譯器將組合語言轉換為機器碼。


### 12.5 符號解析與重定位

- **符號解析（Symbol Resolution）**：將每個符號參照與一個符號定義連結起來
- **重定位（Relocation）**：將程式碼中的位址調整為實際的記憶體位址

連結器的主要工作就是將多個目的檔合併，解析外部符號，並進行重定位。

### 12.6 靜態連結 vs 動態連結

| 特性 | 靜態連結 | 動態連結 |
|------|---------|---------|
| 執行檔大小 | 較大 | 較小 |
| 記憶體使用 | 每個行程各一份 | 共用一份程式碼 |
| 更新函式庫 | 需重新連結 | 只需更新函式庫 |
| 執行速度 | 略快（無需載入） | 略慢（需動態載入） |
| 相容性問題 | 較少 | DLL Hell / 版本衝突 |

## 13. 程式載入與執行

### 13.1 載入器（Loader）

載入器負責將可執行檔從磁碟載入記憶體並開始執行。

載入步驟：

1. 讀取 ELF 標頭，驗證格式
2. 根據 Program Header 將各區段載入到對應的虛擬位址
3. 建立堆疊與堆積
4. 設定引數（argc, argv）
5. 跳至程式進入點（`_start`）

### 13.2 記憶體布局

```
高位址
┌──────────────────┐
│     環境變數      │
├──────────────────┤
│      堆疊        │  ← RSP（往低位址成長）
├──────────────────┤
│        │         │
│        ▼         │
│                  │
│        ▲         │
│        │         │
├──────────────────┤
│      堆積        │  ← brk（往高位址成長）
├──────────────────┤
│  .bss （未初始化） │
├──────────────────┤
│  .data （已初始化） │
├──────────────────┤
│  .rodata （唯讀）   │
├──────────────────┤
│  .text （程式碼）   │
├──────────────────┤
│      保留區      │
低位址 0x00000000
```

### 13.3 動態連結流程

```c
// 當程式首次呼叫 printf 時：
// 1. 跳至 PLT（Procedure Linkage Table）
// 2. PLT 跳至 GOT（Global Offset Table）
// 3. GOT 初始指向解析器（ld.so）
// 4. 解析器找到 printf 位址並更新 GOT
// 5. 後續呼叫直接跳至 printf
```

這稱為**惰性繫結（Lazy Binding）**。

## 14. 號誌與同步機制

### 14.1 競爭條件（Race Condition）

當多個執行緒同時存取共享資料，且執行結果取決於存取順序時，就產生了競爭條件。

```c
// 競爭條件範例
int counter = 0;

// 執行緒 A
counter++;

// 執行緒 B
counter--;
```

`counter++` 實際上對應三條組合語言指令：

1. `load counter, reg`
2. `add reg, 1`
3. `store reg, counter`

若 A 與 B 交錯執行，最終 counter 的值可能是 -1、0 或 1。

### 14.2 臨界區段（Critical Section）

臨界區段是存取共享資源的程式碼區域，必須滿足：

- **互斥（Mutual Exclusion）**：同一時間只有一個執行緒在臨界區段
- **前進（Progress）**：若無執行緒在臨界區段，等待的執行緒應可進入
- **有限等待（Bounded Waiting）**：每個執行緒等待的時間有限

### 14.3 號誌（Semaphore）

號誌是一個整數變數 + 兩個原子操作：

```c
// P / wait：將號誌減 1，若為負則阻塞
void wait(sem_t *s) {
    s->value--;
    if (s->value < 0)
        block_and_add_to_queue(s->queue);
}

// V / signal：將號誌加 1，喚醒一個阻塞的執行緒
void signal(sem_t *s) {
    s->value++;
    if (s->value <= 0)
        wake_up_one(s->queue);
}
```

- **二元號誌（Binary Semaphore）**：值為 0 或 1，用於互斥
- **計數號誌（Counting Semaphore）**：值 > 1，用於有限資源的管理

### 14.4 互斥鎖（Mutex）

Mutex 是二元號誌的特例，使用上更簡潔：

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

void *worker(void *arg) {
    pthread_mutex_lock(&lock);
    // 臨界區段
    counter++;
    pthread_mutex_unlock(&lock);
    return NULL;
}
```

### 14.5 條件變數（Condition Variable）

讓執行緒在特定條件下等待，條件滿足時被喚醒：

```c
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
int ready = 0;

void *producer(void *arg) {
    // 生產資料...
    pthread_mutex_lock(&lock);
    ready = 1;
    pthread_cond_signal(&cond);
    pthread_mutex_unlock(&lock);
    return NULL;
}

void *consumer(void *arg) {
    pthread_mutex_lock(&lock);
    while (!ready)
        pthread_cond_wait(&cond, &lock);
    // 消費資料...
    pthread_mutex_unlock(&lock);
    return NULL;
}
```

### 14.6 讀寫鎖（RWLock）

區分讀取與寫入：

- 多個讀取者可同時持有鎖
- 寫入者需要獨佔鎖
- 適合讀多寫少的場景

## 15. 死結

### 15.1 死結的定義

死結（Deadlock）發生於一組行程中的每個行程都在等待其他行程持有的資源，導致所有行程永遠無法繼續執行。

### 15.2 死結的必要條件

1. **互斥（Mutual Exclusion）**：資源一次只能給一個行程使用
2. **持有並等待（Hold and Wait）**：行程持有資源的同時還在等待其他資源
3. **不可搶佔（No Preemption）**：資源不能強制被取走
4. **循環等待（Circular Wait）**：存在一組行程形成等待循環

```
行程 A ──等待──► 資源 X
  ▲                │
  │                ▼
 資源 Y ◄──等待── 行程 B
```

### 15.3 死結處理策略

#### 預防（Prevention）

確保至少一個必要條件不成立：

- 打破互斥：盡量使用共享資源
- 打破持有並等待：要求行程一次申請所有資源
- 打破不可搶佔：允許搶佔資源
- 打破循環等待：對資源編號，要求按順序申請

#### 避免（Avoidance）

使用**銀行家演算法（Banker's Algorithm）**，在資源分配前判斷是否會導致不安全狀態。

#### 偵測與恢復（Detection & Recovery）

- 定期檢查是否有死結
- 恢復方式：終止行程、搶佔資源、回滾

#### 忽略（Ostrich Algorithm）

假設死結發生機率很低，不做任何處理。實際的作業系統（如 Linux 和 Windows）多採用此策略。

## 16. 網路系統程式設計

### 16.1 Socket 模型

Socket 是網路通訊的端點抽象。

```
伺服器                        客戶端
   │                            │
   ▼                            ▼
socket()                      socket()
   │                            │
   ▼                            │
bind()                          │
   │                            │
   ▼                            │
listen()                        │
   │                            │
   ▼                            ▼
accept() ◄──── 連線建立 ──── connect()
   │                            │
   ▼                            ▼
read()/write() ◄─── 資料 ──→ read()/write()
   │                            │
   ▼                            ▼
close()                       close()
```

### 16.2 Socket API 範例（TCP 伺服器）

```c
#include <stdio.h>
#include <sys/socket.h>
#include <netinet/in.h>

int main() {
    int server_fd = socket(AF_INET, SOCK_STREAM, 0);

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port = htons(8080),
        .sin_addr.s_addr = INADDR_ANY
    };

    bind(server_fd, (struct sockaddr*)&addr, sizeof(addr));
    listen(server_fd, 5);

    while (1) {
        struct sockaddr_in client;
        socklen_t len = sizeof(client);
        int client_fd = accept(server_fd, (struct sockaddr*)&client, &len);

        char *msg = "HTTP/1.1 200 OK\r\nContent-Length: 12\r\n\r\nHello World!";
        send(client_fd, msg, strlen(msg), 0);
        close(client_fd);
    }
}
```

### 16.3 I/O 多工

當需要同時處理多個連線時，有以下幾種模型：

| 模型 | 特點 |
|------|------|
| 多行程 | 每個連線一個行程，成本高 |
| 多執行緒 | 每個連線一個執行緒，需同步 |
| select / poll | 單執行緒監控多個 fd，可擴展性有限 |
| epoll (Linux) | 事件驅動，高效處理大量連線 |
| kqueue (BSD/macOS) | 類似 epoll |
| IOCP (Windows) | 非同步 I/O 完成埠 |

### 16.4 epoll 範例

```c
int epfd = epoll_create1(0);

struct epoll_event ev = {
    .events = EPOLLIN,
    .data.fd = server_fd
};
epoll_ctl(epfd, EPOLL_CTL_ADD, server_fd, &ev);

while (1) {
    struct epoll_event events[64];
    int n = epoll_wait(epfd, events, 64, -1);

    for (int i = 0; i < n; i++) {
        if (events[i].data.fd == server_fd) {
            int client = accept(server_fd, NULL, NULL);
            ev.data.fd = client;
            epoll_ctl(epfd, EPOLL_CTL_ADD, client, &ev);
        } else {
            // 處理客戶端資料
        }
    }
}
```

### 16.5 非阻塞 I/O

預設的 Socket 是阻塞的（Blocking），但可設為非阻塞：

```c
int flags = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, flags | O_NONBLOCK);
```

非阻塞 I/O 讓程式可以同時處理多個連線，而不需要多執行緒。

## 17. 安全與保護

### 17.1 記憶體安全

```c
void vulnerable(char *input) {
```

## 19. 附錄：實作範例

### 19.1 簡易 Shell

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

#define MAX_LINE 1024
#define MAX_ARGS 64

int main() {
    char line[MAX_LINE];
    char *args[MAX_ARGS];

    while (1) {
        printf("mysh> ");
        fflush(stdout);

        if (!fgets(line, MAX_LINE, stdin))
            break;

        line[strcspn(line, "\n")] = '\0';

        if (strcmp(line, "exit") == 0)
            break;

        int argc = 0;
        char *token = strtok(line, " ");
        while (token && argc < MAX_ARGS - 1) {
            args[argc++] = token;
            token = strtok(NULL, " ");
        }
        args[argc] = NULL;

        if (argc == 0) continue;

        pid_t pid = fork();
        if (pid == 0) {
            execvp(args[0], args);
            perror("exec failed");
            exit(1);
        } else {
            int status;
            wait(&status);
        }
    }
    return 0;
}
```

### 19.2 生產者—消費者問題

```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

#define BUFFER_SIZE 8

int buffer[BUFFER_SIZE];
int in = 0, out = 0;

pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t empty = PTHREAD_COND_INITIALIZER;
pthread_cond_t full = PTHREAD_COND_INITIALIZER;

void *producer(void *arg) {
    for (int i = 0; i < 20; i++) {
        pthread_mutex_lock(&mutex);

        while ((in + 1) % BUFFER_SIZE == out)
            pthread_cond_wait(&empty, &mutex);

        buffer[in] = i;
        printf("生產: %d\n", i);
        in = (in + 1) % BUFFER_SIZE;

        pthread_cond_signal(&full);
        pthread_mutex_unlock(&mutex);

        usleep(200000); // 0.2 秒
    }
    return NULL;
}

void *consumer(void *arg) {
    for (int i = 0; i < 20; i++) {
        pthread_mutex_lock(&mutex);

        while (in == out)
            pthread_cond_wait(&full, &mutex);

        int val = buffer[out];
        printf("              消費: %d\n", val);
        out = (out + 1) % BUFFER_SIZE;

        pthread_cond_signal(&empty);
        pthread_mutex_unlock(&mutex);

        usleep(400000); // 0.4 秒
    }
    return NULL;
}

int main() {
    pthread_t p, c;
    pthread_create(&p, NULL, producer, NULL);
    pthread_create(&c, NULL, consumer, NULL);
    pthread_join(p, NULL);
    pthread_join(c, NULL);
    return 0;
}
```

### 19.3 簡易記憶體分配器

```c
#include <stddef.h>

typedef struct block {
    size_t size;
    int free;
    struct block *next;
} block_t;

#define METADATA_SIZE sizeof(block_t)
static block_t *free_list = NULL;

static block_t *find_free_block(size_t size) {
    block_t *current = free_list;
    while (current) {
        if (current->free && current->size >= size)
            return current;
        current = current->next;
    }
    return NULL;
}

void *my_malloc(size_t size) {
    if (size == 0) return NULL;

    block_t *block = find_free_block(size);
    if (block) {
        block->free = 0;
        return (void*)((char*)block + METADATA_SIZE);
    }

    // 向系統要求更多記憶體（此處省略 sbrk 細節）
    return NULL;
}

void my_free(void *ptr) {
    if (!ptr) return;
    block_t *block = (block_t*)((char*)ptr - METADATA_SIZE);
    block->free = 1;
}
```

### 19.4 使用 mmap 複製檔案

```c
#include <stdio.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int copy_file(const char *src, const char *dst) {
    int fd_src = open(src, O_RDONLY);
    if (fd_src < 0) return -1;

    struct stat st;
    fstat(fd_src, &st);
    size_t size = st.st_size;

    char *src_map = mmap(NULL, size, PROT_READ, MAP_PRIVATE, fd_src, 0);
    close(fd_src);

    if (src_map == MAP_FAILED) return -1;

    int fd_dst = open(dst, O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd_dst < 0) {
        munmap(src_map, size);
        return -1;
    }

    ftruncate(fd_dst, size);

    char *dst_map = mmap(NULL, size, PROT_READ | PROT_WRITE, MAP_SHARED, fd_dst, 0);
    if (dst_map == MAP_FAILED) {
        close(fd_dst);
        munmap(src_map, size);
        return -1;
    }

    memcpy(dst_map, src_map, size);

    munmap(dst_map, size);
    munmap(src_map, size);
    close(fd_dst);
    return 0;
}
```

### 19.5 自製簡易 HTTP 伺服器

```c
#include <stdio.h>
#include <string.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define PORT 8080
#define BUFFER_SIZE 4096

const char *response =
    "HTTP/1.1 200 OK\r\n"
    "Content-Type: text/html\r\n"
    "Connection: close\r\n"
    "\r\n"
    "<!DOCTYPE html>"
    "<html><head><title>系統程式</title></head>"
    "<body><h1>Hello from 系統程式!</h1></body></html>";

int main() {
    int server = socket(AF_INET, SOCK_STREAM, 0);

    int opt = 1;
    setsockopt(server, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port = htons(PORT),
        .sin_addr.s_addr = INADDR_ANY
    };

    bind(server, (struct sockaddr*)&addr, sizeof(addr));
    listen(server, 5);

    printf("Server running on http://localhost:%d\n", PORT);

    char buf[BUFFER_SIZE];

    while (1) {
        struct sockaddr_in client;
        socklen_t len = sizeof(client);
        int fd = accept(server, (struct sockaddr*)&client, &len);

        recv(fd, buf, BUFFER_SIZE, 0);
        send(fd, response, strlen(response), 0);
        close(fd);
    }

    close(server);
    return 0;
}
```
